# 우리 집 연금 찾기 (Streamlit 프로토타입)

HF 주택연금과 민간 역모기지 상품 9개를 대상으로, 질문에 답하면 상품별로
**가입할 수 있어요 / 확인이 필요해요 / 해당되지 않아요**를 판정해 주는 파이썬 웹앱입니다.
AI 기능 2가지(상품설명서 분석기, 용어 설명 도우미)가 들어 있습니다.

## 1. 실행하기

### 인터넷에 올려서 쓰기 (Streamlit Community Cloud)

1. GitHub 저장소에 이 폴더의 파일을 모두 올립니다. 이미 올렸다면 바뀐 파일만 덮어씁니다.
2. https://share.streamlit.io 에서 **Create app** → 저장소 선택 → Branch `main` → Main file path `app.py` → **Deploy**.
3. **AI 키 넣기**: 앱 목록에서 앱 오른쪽 `⋮` → **Settings** → **Secrets** 칸에 아래를 붙여넣고 저장합니다.

   ```toml
   LLM_PROVIDER = "gemini"
   LLM_API_KEY  = "발급받은_키"
   ```

   `LLM_PROVIDER`는 `gemini`, `openai`, `anthropic` 중 하나입니다. 모델을 바꾸려면 `LLM_MODEL = "모델이름"`을 추가합니다.
   **API 키는 절대 GitHub 파일에 직접 적지 마세요.** 공개 저장소에 올라가면 누구나 쓸 수 있게 됩니다.

### 내 컴퓨터에서 쓰기

```bash
pip install -r requirements.txt
streamlit run app.py
```

AI 키는 `.streamlit/secrets.toml.example`을 복사해 `.streamlit/secrets.toml`로 저장하고 키를 넣습니다.
Secrets 없이도 **관리자 화면 → AI 상품설명서 분석기 → AI 연결 설정**에서 키를 넣으면 그 접속 화면에서만 쓸 수 있습니다.

**AI 키가 없어도 앱은 동작합니다.** 추천 판정은 AI를 쓰지 않고, 용어 도우미는 용어집 검색으로 답합니다. 분석기만 쓸 수 없습니다.

## 2. 화면 구성

| 화면 | 내용 |
|---|---|
| 추천받기 | 질문 1개씩 큰 글씨로 → 상품별 판정과 이유 → **모르는 말 물어보기(용어 도우미)** |
| 용어 물어보기 | 용어 도우미만 따로 쓰는 화면 |
| 상품 DB (관리자) | **변경 알림함** / 상품 DB · 질문 변경 영향도 / **감시 대상** / **AI 상품설명서 분석기** / **변경 이력** |
| 사이드바 | 발표용 예시 인물 4명 (누르면 결과로 바로 이동) |

## 3. AI 기능

### ① AI 상품설명서 분석기 (관리자 화면)

1. 비교할 상품을 고르고, 상품설명서·공지를 붙여넣거나 파일(txt, pdf)로 올립니다.
2. AI가 가입연령, 주택가격 기준, 대상 주택, 실거주, 지급기간, 한도, 금리, 판매 상태를 **정해진 형식(JSON)**으로 뽑습니다.
3. 프로그램이 AI 결과를 검증합니다.
   - 허용되지 않은 값(예: 정해진 목록에 없는 주택 유형)은 버리고 '주의' 표시
   - 근거 문장이 원문에 없으면 '근거 문장이 원문에서 확인되지 않음' 표시 (AI가 지어냈을 가능성)
4. 현재 DB와 항목별로 비교해 **변경 / 새로 확인 / 같음 / 문서에 없음**으로 나눕니다.
5. 관리자가 근거 문장을 보고 **체크한 항목만** 승인·반영됩니다.
   - 판매 상태, 최소 연령: 판정 Rule까지 바로 바뀌어 추천 결과에 즉시 적용
   - 가격 기준선, 실거주, 주택 유형: '질문 수정 필요'로 표시 (질문 선택지까지 바꿔야 하므로)
6. **변경 이력** 탭에 승인자·시각·이전→이후·후속 조치가 남고, 반영된 `products.json`을 내려받을 수 있습니다.

**시연 방법**: 분석기 탭의 예시 문서 버튼 2개를 쓰세요. 둘 다 시연용 가상 문서입니다.
- 하나생명 상품설명서 → 가입연령 55세→60세 변경 감지 → 승인하면 58세 부부가 '해당되지 않아요'로 바뀜
- 신한은행 판매 종료 공지 → 판매 종료 감지 → 승인하면 결과에서 '해당되지 않아요'로 이동

### ② 용어 설명 도우미 (결과 화면, 용어 물어보기 화면)

- `data/glossary.json`(용어집 19개)과 상품 DB, 그 사용자의 판정 결과**만** 근거로 쉬운 말로 답합니다.
- 지시문에 "자료에 없으면 모른다고 답하기, 가입 권유 금지, 금액 추정 금지"를 넣었고,
  답변에 권유 표현(가입하세요, 추천합니다 등)이 있으면 프로그램이 안내 문구를 덧붙입니다.
- AI 연결이 안 되면 용어집 검색으로 대신 답합니다.

### AI를 어디에 쓰고 어디에 안 썼나

| 영역 | 담당 | 이유 |
|---|---|---|
| 가입 가능 여부 판정 | Rule 엔진 (AI 아님) | 금융 판단은 근거를 설명할 수 있어야 함 |
| 상품 DB 갱신 | AI 추출 → 프로그램 검증 → 사람 승인 | 문서 읽는 비용은 줄이고, 오류는 사람이 거름 |
| 용어 설명 | AI (근거 자료 한정, 권유 금지) | 이해를 돕되 환각·권유 위험 차단 |

## 4. HF 예상 월지급금 계산

- 근거: `data/hf_payment_table.json` — HF 월지급금 예시표(2026.3.1 기준, 종신 정액형, 일반주택, 부부 중 나이가 적은 분 기준, 주택가격은 **시세**)
- 계산: HF 표는 "시세 × 나이별 1억당 금액, 단 나이별 상한까지" 모양이라 이 규칙으로 계산하면 표 전체가 ±0.1만 원 안에서 재현됩니다.
  5세 단위 사이의 나이는 1억당 금액과 상한을 선형 보간합니다. 표가 12억·80세까지라 그 이상은 12억·80세 기준으로 계산하고 화면에 그렇게 적습니다.
- 질문: 공시가격 12억 이하이고 55세 이상이면 **Q3-1 집 시세**를 숫자로 묻습니다. 시세를 입력하면 우대방식의 '시세 2.5억 미만?'(Q7-1)은 자동으로 판단해 묻지 않습니다.
- 표시: 결과 화면 맨 위에 HF 종신 정액형 예상 월지급금, 확정기간·우대·대출상환 방식 카드에는 종신 대비 많고 적음을 안내합니다. 이 방식들의 정확한 금액은 HF 표를 확보하면 같은 방식으로 추가할 수 있습니다.
- 매년 3월 HF가 표를 바꾸면 `hf_payment_table.json`의 숫자와 `effective_date`만 고치면 됩니다.

## 4-1. 상속 시뮬레이션과 가족 리포트

- **상속 시뮬레이션** (결과 화면): 주택연금에 가입했을 때 / 가입하지 않았을 때 / 가입하지 않고 자녀가 같은 생활비를 드렸을 때, N년 뒤 자녀에게 남는 금액을 그래프로 비교합니다.
  - 대출잔액: 초기보증료(주택가격의 1.0%)에서 시작, 매월 월지급금을 더하고 (금리 + 연보증료 0.95%)를 월 복리로 가산 (2026.3.1 기준)
  - 집값 상승률(기본 연 1%)과 대출금리(기본 연 4%, COFIX + 0.85%p 수준 가정)는 슬라이더로 바꿀 수 있음
  - 대출잔액이 집값을 넘는 시점을 찾아 HF **비소구**(자녀에게 청구하지 않음)를 안내
- **가족과 함께 보기**: 카카오톡·문자로 보낼 메시지와 링크, 인쇄용 **가족 리포트(HTML)** 내려받기
  - 링크(`?r=...`)를 열면 같은 결과와 가정이 그대로 복원되고 '가족이 보낸 결과' 안내가 나옵니다. 링크에는 이름·주소가 들어가지 않습니다.
  - Secrets에 `APP_URL = "https://내앱.streamlit.app"`을 넣으면 완성된 링크가 만들어집니다.
- 계산 코드는 `engine.py`의 `simulate_inheritance`, 공유·리포트는 `family.py`

## 4-2. 상품 조건 변경 자동 감시 (AI 업무 자동화)

**흐름**: 공식 상품 URL 수집 → 본문 텍스트 추출 → 이전 지문과 비교(같으면 종료, AI 호출 없음) → AI가 핵심 항목 추출 → 기존 DB와 비교 → 변경 발견 시 AI 변경 요약 → **관리자 알림** → 앱 '변경 알림함'에서 승인 → DB 반영

| 구성 | 파일 |
|---|---|
| 감시 대상 9곳 (팀 조사 시트) | `data/sources.json` |
| 수집·지문·변경 신호·비교·요약 | `monitor.py` |
| 정기 실행 스크립트 | `scripts/run_monitor.py` |
| 매일 자동 실행 + GitHub 이슈 알림 | `.github/workflows/monitor.yml` |
| 승인 결과를 저장소에 바로 저장 (선택) | `gh_store.py` |

**감시 규칙**
- robots.txt가 막았거나 확인이 안 되는 사이트는 수집하지 않습니다 (시트의 '반자동' 대상은 관리자가 정기 확인).
- 접속 시각처럼 매번 바뀌는 줄은 빼고 본문 지문을 만들어, 내용이 실제로 바뀌었을 때만 AI를 호출합니다.
- 변경 신호: 준법감시인 **심의필 번호** 변경, **판매 종료·중단 문구**, 상품 페이지 **삭제(404)**.
- 본문이 거의 비어 있으면(스크립트로 그리는 페이지) 오류로 보고합니다.
- 금리·기타 탭은 '참고' 등급, 상품 조건 변경·판매 종료는 '중요' 등급으로 알립니다.

**설정 방법 (GitHub Actions로 매일 자동 실행)**
1. GitHub 저장소 → **Settings → Secrets and variables → Actions → New repository secret**에 `LLM_PROVIDER`, `LLM_API_KEY`를 넣습니다. (Streamlit Secrets와 같은 값)
2. 저장소 → **Actions** 탭 → '상품 조건 변경 감시' → **Run workflow**로 한 번 실행해 봅니다. 이후 매일 08:47(한국시간)에 자동 실행됩니다.
3. 변경이 발견되면 **GitHub 이슈**가 생기고, 저장소를 Watch 중인 팀원에게 메일로 알림이 갑니다. (선택) `NOTIFY_WEBHOOK_URL`에 슬랙·디스코드 웹훅 주소를 넣으면 메신저로도 옵니다.
4. 알림은 `data/alerts.json`에 저장되고, Streamlit 앱 관리자 화면 **'변경 알림함'**에 '승인 대기'로 표시됩니다.
5. (선택) Streamlit Secrets에 `GITHUB_TOKEN`(이 저장소 Contents 읽기/쓰기 권한 토큰)과 `GITHUB_REPO = "아이디/저장소"`를 넣으면, 앱에서 승인할 때 `products.json`이 저장소에 바로 커밋되어 영구 반영됩니다.

**주의: 한국 금융사 사이트가 해외 서버 접속을 막을 수 있습니다.** GitHub Actions와 Streamlit Cloud는 해외 서버라, 수집이 실패하면 팀원 PC에서 `python scripts/run_monitor.py`를 실행하세요 (윈도우 작업 스케줄러로 매일 실행 가능). 결과 파일(`data/alerts.json`, `data/snapshots/`)을 저장소에 올리면 앱에 표시됩니다.

**시연**: 관리자 화면 → 변경 알림함 → '시연용 변경 감지 실행'은 예시 문서를 '새로 수집된 페이지'로 넣어 같은 파이프라인을 돌립니다 (AI 키 필요).

## 6. 상품 조건을 직접 고칠 때

`data/products.json`만 고치면 됩니다. 조건 형식:

```json
{"label": "부부 중 한 분이 만 55세 이상",
 "cond": {"field": "age_older", "op": ">=", "value": 55}}
```

- `field`: 질문 id(`houses`, `price`, `type` …) 또는 나이(`age_self`, `age_older`, `age_younger`)
- `op`: `in`, `>=`, `<=`, `between`
- `check_values`: 이 답이면 '확인 필요' / `otherwise`: 조건 불충족 시 예외 규칙
- `sale_status`: `판매 중`이 아니면 '확인 필요', `판매 종료`면 '해당되지 않아요'
